# Чеклист публикации на GitHub

На данном этапе **ничего не публиковалось**. Не выкладывайте исходный `qstat.zip` и объединённые мобильные архивы как есть.

1. [ ] Смените/отзовите действующие API-токены, пароли БД/AMI и внешних сервисов, если они были в исходном архиве и планируются к публичной публикации; оцените также историю чатов/резервных копий.
2. [ ] Сделайте отдельный публичный `qstat.inc.php.example` с placeholders. Настоящий `qstat.inc.php` добавьте в `.gitignore` и проверьте отсутствие в **истории коммитов**.
3. [ ] Ни один Google service-account JSON, Firebase Admin SDK key, APNs `.p8`, Android signing keystore, Apple `*.p12`, provisioning profile не должен попасть в Git.
4. [ ] Проверьте `iiko_client.php`, `night_miss.php`, `index.php`, `recordings.php`, `INSTALL.txt`, SQL-дампы на реальные номера, домены, персональные данные, endpoint-ключи и конфиденциальные значения. Отдельно проверьте `recordings.php` на контроль доступа.
5. [ ] Уберите из примеров абсолютные внутренние IP, домены и пути к живым секретам; замените переменные на `YOUR_DOMAIN`, `YOUR_PROJECT_ID`, `YOUR_DB_NAME`.
6. [ ] Убедитесь, что HTTPS обязателен и в AndroidManifest можно отключить cleartext (`usesCleartextTraffic`).
7. [ ] Добавьте LICENSE только после явного выбора владельцем прав. Без лицензии проект **не является автоматически open source**.
8. [ ] Проверьте права на внешние кодовые компоненты, иконки и содержимое дампов; при необходимости добавьте атрибуции.
9. [ ] Прогоните сканер секретов (например, gitleaks) и просмотрите `git diff --cached`, `git log -p` перед первым push.
10. [ ] Публикуйте сначала приватный репозиторий, просмотрите результат и только после явного согласования сделайте его публичным.

В исходном `INSTALL.txt` есть исправляемые ошибки: `cc_push_event` вместо `cc_push_events`, обрезанные длинные строки cron; не использовать его как готовую инструкцию для развёртывания.

Текущий scope: перенос `call.php`/`recordings.php` в `api.php` отложен на следующий релиз по решению владельца. Оценку рисков оставить в истории решений; рабочие PHP-файлы не менять.
