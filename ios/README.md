# FreePBX QStat — iOS native app

Нативный клиент на SwiftUI для JSON API проекта `freepbx-qstat-dashboard`.

## Требования
- Xcode 15 или новее
- iOS 17.0+
- Доступный `api.php` и `recordings.php` на сервере FreePBX

## Открытие проекта
1. Распакуйте архив.
2. Откройте `FreePBXQStat.xcodeproj` в Xcode.
3. Выберите Team в Signing & Capabilities (если нужно установить на физическое устройство).
4. Выберите iPhone Simulator или подключённый iPhone и нажмите Run.

## Подключение
На первом запуске введите полный адрес до `api.php`, например:

`https://pbx.example.ru/qstat/api.php`

Укажите токен из `$api_tokens` в `qstat.inc.php`. Если на сервере `$api_auth_enabled = false`, токен можно оставить пустым.

Адрес сохраняется в UserDefaults, токен — в iOS Keychain.

## Важно про recordings.php и безопасность
Приложение ожидает, что `recordings.php` находится в том же каталоге, что и `api.php`. Используется существующий контракт веб-версии:
- входящий: `recordings.php?uniqueid=<callid>`;
- исходящий: `recordings.php?outgoing_id=<id>`.

В текущем `recordings.php` из репозитория проверка Bearer-токена не реализована. Приложение передаёт токен в заголовке, но сам скрипт его пока не проверяет. Поэтому доступ к записям фактически не защищён токеном API. Если сервер доступен из интернета, рекомендуется добавить в `recordings.php` такую же проверку `$api_auth_enabled` / `$api_tokens`, как в `api.php`, прежде чем считать записи защищёнными.

## Важно про HTTP
Поддержка `http://` включена в Info.plist для совместимости с локальными/тестовыми серверами. Для реального использования рекомендуется HTTPS: обычный HTTP не шифрует токен и содержимое запросов.

## Совместимость статуса исходящих
Фильтры `NO ANSWER` и `BUSY` должны работать раздельно. Для этого на сервере необходимо установить обновлённый `api.php` из каталога `server-api-update` в комплекте v1.4. KPI «Не дозвонились» в режиме «Все» по-прежнему суммирует `NO ANSWER` + `BUSY`.


## Обновление API для раздельной фильтрации исходящих

В v1.4 добавлен `server-api-update/api.php`. Замените им действующий серверный `api.php` (сначала сохраните резервную копию). После замены `status=NO%20ANSWER` возвращает только `NO ANSWER`, а `status=BUSY` — только `BUSY`. В режиме без фильтра KPI «Не дозвонились» остаётся суммой обоих статусов.
